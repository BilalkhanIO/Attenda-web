# Attenda Web — Post-Expansion Gap Audit (2026-08)

Branch: `claude/zealous-sagan-8aa4gb` · Scope: all 44 route files under `src/app/`, every component dir, the full `src/lib/` (api.ts / queries.ts / query.tsx / auth.tsx / i18n.ts / proxy.ts), diffed against the API's 26-router MOUNTS list (`attenda-api/src/app.ts:120-150`). API-side defects catalogued in `attenda-api/docs/AUDIT_2026-08.md` are **not** re-reported here; where the web must adapt once they're fixed, it's called out inline as **[API-adapt]**.

## Executive summary — top 10 actionable items (severity × effort)

1. **[Broken core flow] Plain employees cannot use the web for their own leave or check-in.** The Leave page's only two data sources are `GET /leave/requests/team` (needs `leave.view_team`/`leave.approve`) and the org-wide list (`leave.view_all`) — an employee lands on `scope='team'` (`src/app/leave/page.tsx:80,124`), the request 403s, the global toast fires, and their **own request history is nowhere** (`GET /leave/requests/me` has no client method in `src/lib/api.ts` at all; `DELETE /leave/requests/:id` cancel likewise). Meanwhile the employee dashboard ("My Day", `src/app/dashboard/page.tsx:108-166`) has **no check-in/check-out button** — the personal punch UI lives only on `/attendance`, whose nav item is hidden behind `attendance.view_team` (`src/components/layout/DashboardLayout.tsx:42`). Web employees can check in only by typing the URL.

2. **[XSS] Blog post content is rendered with `dangerouslySetInnerHTML` through a regex "markdown" converter that never HTML-escapes** (`src/app/blog/[slug]/page.tsx:68-81,200`) — any raw HTML/`<script>` in `post.content` is injected verbatim into the public marketing page. The JSON-LD block (`:123`) injects `JSON.stringify(jsonLd)` without escaping `<`, so `</script>` inside a post title also breaks out. Authors are platform staff (semi-trusted), but this is stored XSS on the anonymous-facing site; escape first (or use a real sanitizer) and serialize JSON-LD with `<` → `<`.

3. **[Broken link] Sidebar "WhatsApp" points to `/settings/whatsapp` — a route that does not exist** (`src/components/layout/DashboardLayout.tsx:68`; `src/app/settings/` contains only `announcements/`, `onboarding/`, `profile/`, `page.tsx`). Every org with the whatsapp feature and `org.whatsapp.update` gets a nav item that 404s; the actual UI is a modal on `/settings` (`src/app/settings/page.tsx:348`).

4. **[Dead-end money flow] Payroll recall exists server-side but has no web method or button.** `payrollApi` (`src/lib/api.ts:283-295`) omits `POST /payroll/:id/recall`, `GET /payroll/me`, and `GET /payroll/:id`; the process-confirm even claims "This action cannot be undone" (`src/app/payroll/page.tsx:378`) and the approvals reimburse error tells the admin to "recall the payroll period first" (`src/app/approvals/page.tsx:261`) — an instruction the UI cannot perform. Employees also have **no payslip view** (`/payroll/me` unused; payslip download renders only for `payroll.view` holders inside a processed run, `payroll/page.tsx:298-301`).

5. **[Stale-by-design settings page]** `/settings` is a cluster of drift: it registers a real query at the **root** users key (`queryKey: keys.users.all` with `limit: 1000`, `src/app/settings/page.tsx:159`) even though the API caps `limit` at 100 (`attenda-api/src/routes/users.ts:196`) — so the Access Control user picker silently truncates at 100 employees and refetches on every users-invalidation; org settings are cached under three divergent keys (`['org-settings']` here, `keys.org.all` in `queries.ts:664-668`, plus `TrialBanner.tsx:26` fetching raw); and Save PUTs the **entire seeded settings object** back (`settings/page.tsx:167-170,239`) — round-tripping plan/status/rates it never edits. **[API-adapt]** once API exec-#4 lands (`ORG_SETTINGS_SELECT`), the echo no longer leaks `wa_access_token`, but the page should still send only edited fields.

6. **[Permission-gating gap] `/settings` renders full edit UI for anyone, then 403s on every action.** Nav gates on `org.settings.view`, which the API never enforces (API audit Appendix A) — `GET /org/settings` is open to all members, so any employee who visits `/settings` gets editable General Config, network editor, and a QR card whose `GET /org/qr-code` 403-toasts on mount (`settings/page.tsx:162`). No `hasPermission('org.settings.update')` check anywhere on the page (contrast `WebhooksCard.tsx:47,71` which does it right). Same class: kudos delete button shows for `org.settings.update` while the API accepts author-or-`org.settings.update` (`kudos/page.tsx:186` — fine), but Employees' import/create buttons are gated ✓ — the settings page is the outlier.

7. **[i18n wired but unplugged] `setDefaultCurrency()` and `setLocale()` are never called** (grep: zero call sites outside `i18n.ts`), so every `formatCurrency` without an explicit code renders **USD** regardless of the org's `currency` column — payroll KPIs/rows (`payroll/page.tsx:219-288`), overtime summary, employee "Rate" cells (which additionally hardcode `$` template strings, `employees/page.tsx:294,470`). Capabilities wiring already exists for timezone (`auth.tsx:50-59`) — add currency to `/users/me/capabilities` or read it from org settings and call the setter.

8. **[Invisible scheduled announcements]** After scheduling, an announcement disappears: the list endpoint returns published-only, the page acknowledges this in a comment (`src/app/settings/announcements/page.tsx:224-231`), and there is no pending-scheduled list or cancel. Compounding it, **employees have no announcements reader at all** — announcements 2.0 surfaces to non-senders only as a `line-clamp-1` row in the notification dropdown (`DashboardLayout.tsx:399`). **[API-adapt]** needs `GET` including own scheduled items + a cancel endpoint; the web page should be built to consume both.

9. **[Approvals inbox blind spots]** The unified queue never shows **absent-status context or corrections submitted by web users because corrections cannot be submitted from the web**: `POST /attendance/corrections` and `GET /attendance/corrections/me` have no client methods (the only "corrections" string in `src/app` outside approvals is marketing copy in `page.tsx`). Same one-sided story for shift swaps (`POST /shifts/swaps` unused — web can approve swaps but never request one) and overtime rules vs employee visibility. Managers review a queue that only mobile users can fill.

10. **[CSP will break uploads when enforced]** The report-only CSP sets `connect-src 'self' <api-origin>` (`src/proxy.ts:48-59`), but the document upload flow does a raw `fetch` **PUT to a presigned S3 URL** (`src/components/documents/UploadDocumentModal.tsx:110-115`) and avatars/receipts/QR images load from S3/api origins while `img-src` is `'self' data: blob:`. Flipping this header to enforcing as-is bricks uploads, avatars, payslip QR. Add the S3 origin(s) to `connect-src`/`img-src` (or proxy uploads) before enforcement; also `script-src 'unsafe-inline'` still needs the nonce work noted in the file.

## 2. Incomplete flows / dead ends

- **Leave for employees** — exec #1. Also: the team scope has no pagination while HR scope does; comment admits it (`leave/page.tsx:78-79`).
- **No check-in from dashboard** — exec #1. The `/attendance` personal panel itself is complete (manual check-in/out, breaks, late notice submit/cancel, leave-check) but unreachable via nav for the people it serves.
- **Kudos feed pagination missing**: API supports `page/limit`; `kudosFeedQuery` deliberately fetches "latest 100" with no load-more (`queries.ts:403-409`, `kudos/page.tsx:271-281`). Corrections/expenses lists on approvals also unpaginated, mirroring the API's `take: 200` cap — fine today, **[API-adapt]** when API pagination lands.
- **Payroll month filter is client-side**: `GET /payroll` accepts `month`/`year` (`attenda-api/src/routes/payroll.ts:23-26`) but the page fetches **every period ever** then `.find()`s (`payroll/page.tsx:58-60`). Grows unboundedly with org age.
- **Payroll OT display hardcodes 1.5×** (`payroll/page.tsx:275`) — matches the API's current hardcoded math, but **[API-adapt]**: when API exec-#6 (overtime-rules engine in payroll) is fixed, this derived column and the CSV export become wrong; render server-provided `overtime_pay` instead of recomputing.
- **Scheduled announcements vanish + no employee reader** — exec #8; also uses `window.confirm` (`settings/announcements/page.tsx:157`) instead of the app's `ConfirmDialog` (a11y + style drift).
- **No notifications archive page**: the bell dropdown fetches page 1 (20 items) with a "Refresh" footer (`DashboardLayout.tsx:172-180,426-435`); `notificationApi.getAll` supports paging — older notifications are unreachable.
- **Employees list**: no `status` filter dropdown though the server supports it (`usersListQuery` passes it; UI only offers department/role, `employees/page.tsx:351-374`) — inactive staff can't be isolated (nor reactivated, §1.6).
- **CSV import is fragile**: naive `line.split(',')` parsing — quoted fields containing commas corrupt rows (`employees/page.tsx:316-327`); no template download, no preview, errors array from the API (`{created, skipped, errors}`) is never shown (only counts, `:234`). **[API-adapt]** API exec-#5 (import skips role validation): until fixed, the web should whitelist `role` values client-side before sending.
- **422 field errors are swallowed**: the API returns `details: [{path, message}]` on validation errors (`attenda-api/src/middleware/errorHandler.ts:11-17`) but `getApiError` reads only `error`/`message` (`src/lib/utils.ts:124-131`) — forms without client-side zod (settings, admin org detail, shifts modals) surface a bare "Validation failed".
- **Login ignores the `?redirect=` param** the proxy sets (`proxy.ts:92` vs `login/page.tsx:58,72` — always `/dashboard`); deep links lost after auth.
- **Error states**: newer TanStack pages rely on the global toast + skeletons but render no inline error/retry state (approvals, kudos, documents, announcements) — a failed query looks identical to "empty". Old ad-hoc pages (analytics `Promise.allSettled` with silent failures, `analytics/page.tsx:41`) can render zeroed charts on error.

## 3. Consistency drift

- **TanStack Query adoption is bimodal.** Converted: approvals, dashboard, documents, kudos, leave, employees, expenses, overtime, remote, performance(+goals), swaps, announcements, onboarding, admin/orgs list, most settings cards. Still ad-hoc `useState`+`useEffect(runDeferred)`: **attendance (1,006 lines), shifts (1,145), shifts/templates, payroll, analytics, settings/profile, admin/blog, admin/plans, admin/users, admin/logs, admin/pending, admin/orgs/[id], admin dashboard** — plus `WebhooksCard`, `HolidaysCard`, `DepartmentsCard` components. These get no SSE invalidation, no focus refetch, no global error handling.
- **Query-key hygiene**: inline ad-hoc keys `['org-settings']`, `['org-networks']`, `['attendance-qr']`, `['whatsapp-settings']`, `['audit-logs', page]`, `[...keys.org.all,'departments-tree']` bypass the factory; `orgSettingsQuery`/`whatsappSettingsQuery` exist in `queries.ts:664-674` but the settings page doesn't use them → duplicate caches that invalidate independently (exec #5).
- **Toast/error style**: three generations coexist — global QueryCache toast (`query.tsx`), per-mutation `onError: toast.error(getApiError(...))` (redundant where the global handler exists), and try/catch-toast in ad-hoc pages. `window.confirm` in announcements vs `ConfirmDialog` everywhere else.
- **DataTable adoption**: only employees, leave, and admin OrgsTable use `DataTable` with server paging/sorting. Payroll, attendance, shifts, overtime summary, admin blog/users/logs still use raw `Table` or bespoke rows — no sorting, no pagination affordance even where the API paginates (admin audit logs page has its own Prev/Next).
- **Modal a11y (new components)**: `Modal` has Escape/label/focus-restore ✓ but **no focus trap** — Tab walks into the background page (`ui/index.tsx:311-317`); `Dropdown` is a custom listbox with **no ARIA roles, no `aria-expanded`, no keyboard arrow/type-ahead support** (`ui/index.tsx:892-970`) — a regression vs the native `Select` it replaced (the a11y pass fixed labels/`aria-label`s but skipped composite widgets); `ActionMenu` items have no `role="menu"`/keyboard nav (`ui/index.tsx:853-872`).
- **Permission-gating**: settings page (exec #6); `/settings` nav keys off `org.settings.view` which the API doesn't enforce — **[API-adapt]** if the API starts enforcing it per its Appendix A, nothing breaks, but if it instead *drops* the key, the nav item disappears for everyone; align on `org.settings.update`.
- **`platform_assistant` is unroutable**: `proxy.ts:95-104` and `DashboardLayout.tsx:123-127` both assume `platform_admin` is the only platform role. `AdminLayout` nav already declares per-item `platform_permissions` (`AdminLayout.tsx:28-37`) anticipating assistants, but an assistant's JWT role isn't `platform_admin`, so the proxy shunts them to the tenant dashboard where every query 403s. (API's `admin.ts` hard-gate has the same bug — API audit §3.5 — fix both together.)
- **Currency/`$` hardcodes**: `employees/page.tsx:294,470` (also exec #7).

## 4. Client architecture

- **api.ts is fine at 665 lines** (not yet a god object) — 19 cohesive per-domain exports; the real issue is **coverage** (§1) not size. `queries.ts` (788) is the growing file; consider per-domain splits when it passes ~1k.
- **Dead exports**: `adminApi.sendAnnouncement` (`api.ts:659-660` — duplicates `announcementsApi.send` and posts to the tenant announcements route from the *platform* client; nothing calls it), `orgRbacApi.ensureSystemRoles` (`api.ts:583`), `attendanceApi.getEmployee` (`api.ts:186`), `attendanceApi.getMyLateNotices` (`api.ts:210`), `usersApi.getPermissions/updatePermissions` are used ✓, `leaveApi.getMyBalance` used ✓.
- **INVALIDATE_SCOPES completeness**: the 6 scopes (`DashboardLayout.tsx:98-105`) exactly match today's `OrgEventType` union ✓, and unknown scopes are ignored by design ✓. **[API-adapt]**: when the API adds `payroll_processed` / `document_added` / `employee_created` / `onboarding_completed` / `holiday_changed` events (API audit §2.2/§7.4), add mappings to `keys.documents.all`, `keys.onboarding.all`, `keys.users.all`, org keys — documents/onboarding/kudos/announcements currently have **no** live invalidation path at all.
- **Duplicate components**: `AdminLayout` re-implements the entire SSE stream + notification bell (~150 lines) copied from `DashboardLayout` (`AdminLayout.tsx:83-190` vs `DashboardLayout.tsx:129-235`), including a `NOTIF_ICONS` map that has already drifted (no `announcement`/`document_added` entries). Extract a `useNotifications` hook + `<NotificationBell/>`. `CardElapsed`/`LiveDuration` + `totalBreakMinutes` + `fmtHours` are triplicated across dashboard/attendance pages (`dashboard/page.tsx:16-53`, `attendance/page.tsx:60-117`). Two AI-chat implementations (`AIChatWidget.tsx` floating on every page + `/analytics/ai` page) call the same endpoint with separate message-state logic.
- **`NOTIF_ICONS` contains 6 types the API never creates** (`remote_no_reply`, `payslip_ready`, `shift_reminder`, etc. — API audit Appendix B); harmless fallback, but signals the map was written to the type union, not reality.
- **Auth**: `hasFeature` fails **open** when capabilities are null/failed (`auth.tsx:178-182`) while `hasPermission` fails closed — a capabilities fetch failure shows feature-gated nav items whose pages then 403. Consider failing closed after `capabilitiesLoading` settles.

## 5. Security / robustness

- **Blog XSS** — exec #2 (the one genuinely dangerous unsafe render; no other `dangerouslySetInnerHTML` in tree).
- **Tokens in JS-readable cookies**: access+refresh in non-HttpOnly cookies (`api.ts:19-41`) so the proxy can read them — a deliberate tradeoff, but it makes exec #2 a full account-takeover primitive; `secure` flag is set only when the *setting* page is https (`:23`), and no `__Host-` prefix. Refresh single-flight + rotation handling is well done (`api.ts:76-97`) ✓; 401→refresh→retry doesn't cap retry storms beyond `_retry` ✓.
- **CSP report-only gaps** — exec #10; additionally no `report-to`/`report-uri` endpoint is configured, so "report-only" reports only to devtools consoles.
- **SSE auth via header** (fetch-event-source) rather than `?token=` ✓ — good; the API's query-token fallback (its audit §4.2) is not exercised by the web.
- **Settings PUT echoes the whole org object** — exec #5. Until API exec-#4 ships, `settingsQuery.data` contains `wa_access_token`; it sits in TanStack cache and is re-sent in the PUT body. After the API fix, still trim the payload.
- **Reject/approve race**: approvals `act` mutation guards double-click via `actingOn` per-row ✓, but leave/overtime/remote/swap pages use optimistic flips with rollback ✓ — solid. Payroll `onGenerate`/`onProcess` have no double-submit guard beyond button `loading`.
- **Input constraints missing where the API validates**: shifts modals, admin org detail, settings general config send unvalidated bodies (no zod), so users hit server 422s whose field details are then dropped (§2). Webhook editor validates https + URL ✓; upload modal mirrors the API's 20MB/mime allowlist ✓ (`UploadDocumentModal.tsx:12-28`) — the reference pattern.
- **Upload edge cases**: no client-side timeout/abort on the S3 PUT (a stalled PUT wedges the modal in "Uploading…" until browser timeout; Cancel is disabled while busy, `UploadDocumentModal.tsx:64-68`); orphaned S3 objects if register (step 3) fails — surfaced only as a toast with no retry-register path.
- **QR image**: `settings/page.tsx:333` `<img src={qrQuery.data?.qr_code}>` — if that's a data URI ✓; if an S3 URL, add to CSP `img-src` (exec #10).
- **WebRTC IP detection** (`settings/page.tsx:30-53`) is defunct in modern browsers (mDNS candidates) — the "Local Scan" silently returns nothing; keep only the server-side `detectMyIp`.

## 6. Test coverage holes

39 tests exist: i18n (20), proxy routing decision (8), nav visibility (5), getApiError (3), table empty-state (3). Zero component/page tests. Highest-value additions, in order:

1. **api.ts interceptor** — single-flight refresh (N parallel 401s → one `/auth/refresh`), rotation persistence, remember-me preservation, failure → clearTokens+redirect. This is the most intricate untested logic in the app (`api.ts:76-121`) and a regression here logs everyone out.
2. **Approvals normalization** — the 7-source `Row → ApprovalItem` mapping incl. swap requester/target extraction, `rejectNeedsReason`/`rejectNoteOptional` matrix, and sort (`approvals/page.tsx:145-201`). Pure function once extracted.
3. **Upload flow state machine** — url→put→register steps, mime/size validation, register-failure leaves step reset (`UploadDocumentModal.tsx:85-138`).
4. **INVALIDATE_SCOPES ↔ keys** — every scope maps to keys that real queries actually use (guards against factory refactors silently killing SSE invalidation).
5. **`useUrlListParams`/`parsePageParam`** + leave optimistic `flipStatus` over both cache shapes (`leave/page.tsx:66-73`).
6. **`renderMarkdown` escaping** — once exec #2 is fixed, lock it in with a test.
7. **CSV import parser** (after replacing the naive split) and payroll CSV quoting (`payroll/page.tsx:152` quotes ✓ but doesn't escape leading `=+-@` — same formula-injection class as the API's csvExport).

## 7. Missing features worth adding (ranked, max 8)

1. **Employee self-service core** — "My leave requests" (+cancel), "My payslips", "My schedule/swaps", check-in button on My Day, correction request form. Closes exec #1/#4/#9 in one coherent "me" surface; every endpoint already exists.
2. **Global search / command palette (⌘K)** — employees, pages, actions. The `q` search contract already spans users/leave/admin orgs; a palette is mostly client work and transforms admin ergonomics.
3. **CSV/XLSX export buttons on every DataTable** (employees, leave, audit logs, overtime summary) — payroll/attendance already have bespoke CSV code to generalize into a `useCsvExport` util (with formula-escape).
4. **Full audit-log page** for tenants (the settings card shows a page-capped list; promote to a filterable DataTable with `action` filter the API already supports, `api.ts:509-510`).
5. **Org switcher / impersonation for platform staff** — admin org detail already loads org users; a scoped "view as org" (read-only token or explicit org_id params) is the single biggest support-tooling gap. Requires API support; design the web shell now.
6. **Bulk actions on employees** (multi-select → deactivate / assign onboarding / set department) — DataTable needs row-selection support; pairs with fixing activate/resend-invite (§1.6).
7. **Session/device management UI** — render-ready card in profile settings for when API ships `GET/DELETE /auth/sessions` (its roadmap #14/top-missing #1). **[API-adapt]** placeholder until then.
8. **Dark/light theme toggle** — the app is dark-only with hardcoded `--dark-*` tokens; marketing pages likewise. Tokenization is already CSS-variable-based, so a light theme is mostly palette work.
